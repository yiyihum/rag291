# 💎🆚💎 Gemma vs Gemma Preferences

This dataset contains on-policy collected preferences generated using [anakin87/gemma-2-2b-ita-sft](https://huggingface.co/anakin87/gemma-2-2b-ita-sft).

⚠️ While this dataset may be valuable for didactic purposes, it is not recommended for training a model using Preference Tuning due to the following reasons:
- The training would be off-policy for your model.
- The dataset was generated with gemma-2-2b-ita-sft, a small model for Italian.

## Motivation

While DPO (Direct Preference Optimization) is computationally efficient and widely adopted by both researchers and practitioners, it has its critiques. The key takeaway is that **DPO may leave some performance gains untapped compared to Reinforcement Learning techniques such as PPO (Proximal Policy Optimization)**.

As highlighted in [Is DPO Superior to PPO for LLM Alignment? A Comprehensive Study](https://arxiv.org/abs/2404.10719), one of the major problems is that DPO is frequently conducted using only **off-policy data** — data generated by models other than the one being trained. While this is a common practice, it is not an inherent requirement of DPO, but it can introduce a distribution shift during training, potentially affecting performance.

Recent evidence (especially [TÜLU 3 technical report](https://arxiv.org/abs/2411.15124), but also [Llama 3 technical report](https://arxiv.org/abs/2407.21783)) indicates that using or **including on-policy data—data generated by the SFT model itself— can be beneficial during DPO**. Notably, in TÜLU 3, this on-policy data was generated offline (i.e., outside the training loop), making the approach both resource-efficient and easy to implement.

## Dataset generation process

The following approach offers a **simple, cost-effective, and reproducible method to generate on-policy data**.

The steps are as follows:
1. Select a source of prompts in your target language.
2. Sample the SFT model to generate 2 responses.
3. Evaluate and rank the responses using a LLM as a Judge (Llama-3.3-70B-Instruct).
4. (optional) If both responses are of low quality, generate an alternative strong response ("llama_response" column).

For detailed information on the generation process, check out this [📓 Kaggle notebook](https://www.kaggle.com/code/anakin87/post-training-gemma-for-italian-and-beyond).

## Description
- prompt: the original prompt, sourced from [sapienzanlp/it-Magpie-Llama-3.1-Pro-300K-Filtered-easy](https://huggingface.co/datasets/sapienzanlp/it-Magpie-Llama-3.1-Pro-300K-Filtered-easy)
- task_category: the original task category
- risposta_1: the first response generated by the model during sampling
- risposta_2: the second response generated by the model during sampling
- feedback_risposta_1: feedback on risposta_1, provided by Llama
- punteggio_risposta_1: the score of risposta_1, assigned by Llama
- feedback_risposta_2: feedback on risposta_2, provided by Llama
- punteggio_risposta_2: the score of risposta_2, assigned by Llama
- best: the best response, as determined by Llama's evaluation.  Possible values: risposta_1, risposta_2, tie, or llama_response (when both scores for risposta_1 and risposta_2 are less than 3).
- llama_response: the alternative response generated by Llama when both risposta_1 and risposta_2 have scores below 3.
- chosen: The selected response, based on the "best" field
- rejected: The non-selected response, based on the "best" field
